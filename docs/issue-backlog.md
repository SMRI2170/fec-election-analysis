## 担当エージェント / 人間が守るルール

1. 原則 **1 Issue = 1 PR**。PRの本文に `Refs #番号` または `Closes #番号` を付ける（本当に完了する場合のみClosesを使用）。
2. PR作成前に関連Issue・既存ファイル・完了PRを読み、実装済みのコードを作り直さない。
3. 新たな数値を論文に追加する前に、実FECファイルの出典・取得日・データ範囲・除外基準・テスト年度を明記する。
4. 非数値データ・曖昧な候補者票・特殊な選挙方式は根拠なく補完しない。テスト年度に過剰適合しない。
5. 実装とテストを通した後、`Python CI` と `FEC source audit` の両方を確認する。
6. 本文の結論は**選別されたサンプルでの予測的関連**とし、全米の因果関係と混同しない。
7. GitHub Actionsの短期アーティファクトと、出典・バージョン管理された再現可能な成果物を区別する。
8. 2010〜2014年の旧XLSや上院への拡張は、提出に必要な精査を終えるまでは後回し。
9. 提出期限は **11月3日17:00** とされるが、年・提出先の最新表示・容量上限はManaba+R/講義資料で再確認する。
