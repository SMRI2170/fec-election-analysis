# Issue #59 — 予備選挙候補者票から作る、リークのない競争特徴量の仕様

**Issue:** [#59](https://github.com/SMRI2170/fec-election-analysis/issues/59)（親 [#50](https://github.com/SMRI2170/fec-election-analysis/issues/50)）

**目的:** 凍結済みの916件は各選挙の「二党得票率」しか持っていない。このIssueでは公式FEC原票の**予備選挙候補者行**から、候補者数・得票集中度・上位候補比率などの競争特徴量を作り、**本選挙に関する情報を一切使わない**ことを構造的に保証したうえで定義する。**このIssueではモデル学習を行わない。**学習と評価は[#60](https://github.com/SMRI2170/fec-election-analysis/issues/60)が行う。

> **対象の境界:** FEC公式2016/2018/2020/2022年の50州Voting House **916選別レコード**（200/241/237/238）。raw原票の地区グループ数は**1,756**で、#49の台帳と一致する。母集団は変更しない。

## 1. 特徴量の定義（スキーマ）

### 1.1 行の粒度と結合キー

| 項目 | 仕様 |
| --- | --- |
| 行の粒度 | 1行 = 1選挙区（年・州・地区） |
| 結合キー | `election_id`（`{年}-House-{州}-{地区}`） |
| 母数 | 凍結済みの916件と**1:1**。原票に行が無い母集団の選挙区は**例外で停止**し、欠落させない |
| 出力先 | `data/processed/primary_features/`（Git管理外） |

### 1.2 1党あたりの特徴量

| 列 | 定義 | 単位 | 備考 |
| --- | --- | --- | --- |
| `{党}_candidates` | 正の数値の予備選挙票を持つ**候補者の数** | 人 | 同一FEC IDの複数行は1人と数える。0票の候補者は数えない |
| `{党}_candidate_votes` | その候補者たちの予備選挙得票の合計 | 票 | 書き込み票は含まない |
| `{党}_hhi` | `sum((v_i / sum v)^2)` | 無次元 | 1.0が単一候補者、0.5が2候補者同数 |
| `{党}_top_share` | 上位候補者の得票 ÷ 党得票合計 | 無次元 | 0〜1 |
| `{党}_log1p_votes` | `log1p(党得票合計)` | 無次元 | 規模の特徴。対数変換 |
| `{党}_writein_votes` | 党帰属付き書き込み票 `W(R)`/`W(D)` の合計 | 票 | **候補者数には含めない**。別列で保持 |
| `{党}_party_subtotal` | FECの `Party Votes:` 小計（予備選挙） | 票 | 無い場合 空欄 |
| `{党}_subtotal_gap` | `小計 − (候補者票 + 書き込み票)` | 票 | 0が算術的整合 |

`{党}_status` は**原因コード**、`{党}_missing` は欠損フラグ（0/1）、`{党}_features_usable` は候補者側の特徴量が使えるか（0/1）である。

### 1.3 行の種類の区別

| 種類 | 見分け方 | 扱い |
| --- | --- | --- |
| 候補者行 | FEC IDが `H` で始まる | 1.2 の特徴量に用いる |
| `Party Votes:` 小計行 | `TOTAL VOTES` 欄の文字 | 照合用に保持。候補者数には含めない |
| `District Votes:` 小計行 | 同上 | 読み取らない（地区全体の合計であり二党ではない） |
| 複合党コード行 | 政党表記に `/` が含まれる（例 `D/IP`） | **主要党1つに帰属**して票を加える。`{党}_fusion_rows` に件数を記録 |
| 両主要党を含む表記（例 `D/R`） | 分割すると R と D が両方出る | **自動帰属しない**。原因コード `ambiguous-fusion-party-code`、欠損フラグを立てる |
| 党帰属付き書き込み行 | 政党表記が `W(R)` / `W(D)` | 候補者数には含めず `{党}_writein_votes` に別の列で保持 |
| 星付き表記（例 `R*`） | 政党表記が `*` で終わる | **帰属しない**（[#14](https://github.com/SMRI2170/fec-election-analysis/issues/14)の未解決案件と同一の扱い） |
| 数値でない予備選挙票 | `Unopposed` / `*` / `#` など | 0補完しない。理由コードを付け、値を空欄のまま残す |

### 1.4 原因コード（優先順）

`ambiguous-fusion-party-code` → `no-candidate-rows` → `unopposed-primary` → `non-numeric-primary-votes` → `zero-primary-total` → `missing-party-subtotal` → `subtotal-mismatch` → `ok`

先頭から順に該当したものを1つだけ記録する。複合党コードの行は候補者行が「ない」のではなく「帰属できない」ので、暧昧コードを優先する。

### 1.5 リークフリーの構造

1. 原票シートを読み込んだ直後に**予備選挙側の列だけを残す**（`_state`・`_district`・`_candidate`・`FEC ID`・`CANDIDATE NAME`・`PARTY`・`PRIMARY VOTES`・`TOTAL VOTES`・`FOOTNOTES`）。**`GENERAL VOTES` 列は構造的に落ちる。**
2. 特徴量の計算は落ちた列だけを使う。
3. 単体テスト `test_general_votes_cannot_reach_a_feature` は、一般選挙票を書き換えて特徴量が一切動かないことを確認する（変異検査で検出されることも確認済み）。

### 1.6 利用可能時点（留保）

**FECのExcelは選挙後に刊行され、本スクリプトの予備選挙候補者行はその最終版からの事後再構成である。**したがって本特徴量は「本選挙の前に何が公式に確定していたか」の証拠ではない。実際の予備選挙は本選挙より前に開かれるため、候補者数と予備選挙得票自体は現実には事前に判明していたはずだが、**本研究が用いた公開資料が事後刊行である**という制約は残る。空席補充（2020年GA-05・IL-04）のように候補者が本選挙前の党指名で決まった地区では、候補者数が確定しない（§3.3）。

### 3.2 特徴量の分布（利用可能な行のみ）

| 年 | 共和党 候補者数 平均/中央値/最大 | 共和党 HHI 平均 | 共和党 上位候補比率 平均 | 民主党 候補者数 平均/中央値/最大 | 民主党 HHI 平均 | 民主党 上位候補比率 平均 | 書き込み票のある選挙区（R/D） |
| --- | --- | ---: | ---: | --- | ---: | ---: | ---: |
| 2016 | 2.345 / 2 / 17 | 0.7209 | 0.7851 | 1.910 / 1 / 9 | 0.7639 | 0.8130 | 28 / 28 |
| 2018 | 2.531 / 2 / 18 | 0.7032 | 0.7683 | 2.834 / 2 / 11 | 0.6225 | 0.7010 | 40 / 43 |
| 2020 | 3.000 / 2 / 16 | 0.6679 | 0.7361 | 2.331 / 2 / 19 | 0.7136 | 0.7810 | 45 / 40 |
| 2022 | 3.147 / 2 / 11 | 0.6286 | 0.7102 | 2.244 / 2 / 17 | 0.7452 | 0.8042 | 48 / 43 |

- 共和党の上位候補比率平均は年を追うほど小さく（0.7851→0.7102）、候補者数平均は大きくなる（2.345→3.147）。**複数候補者が出そろう場合の競争の強さは年によって異なる。**
- 民主党は2018年のみ候補者数平均が大きく（2.834）、HHI平均が小さい（0.6225）。**年・党ごとに競争の構造が違う**ので、単一方向の特徴量では足りない。
- **HHIが1.0（単一候補者）になる選挙区は母集団916件中522件**で、全体の57.0%である。HHIは0.5から1.0の広い範囲を取るが、1.0 の割合が高い。
- 党帰属付き書き込み票の合計は共和党4,537／10,266／13,081／23,611票、民主党8,080／8,216／15,064／13,954票（2016→2022）。**書き込み票の割合は小さい**であり、除外しても党得票の骨格は変わらないが、小規模な選挙区では無視できない。

### 3.3 算術的整合（独立検証）

1. **党小計との差.** 母集団916件の両党すべてで、`小計 − (候補者票 + 書き込み票) = 0`。**1件も差がない。**複合党コード行を主要党に帰属させたことで、Oregon等の融合選挙区の小計も一致する。
2. **凍結母集団との一致.** 正規化済みの `primary_rep_votes` / `primary_dem_votes` と `候補者票 + 書き込み票` も**916件すべてで完全一致**（不一致0件）。特徴量の分解は凍結母集団のPrimary合計を再現する。
3. **例外3件（利用不可）の実情.**
   - **2016年IL-18**: 民主党に正の数値票の候補者が0人。党小計148票は**すべて `W(D)` 書き込み**。候補者側の特徴量は定義できない（`zero-primary-total`）。
   - **2020年GA-05**: 民主党候補者の1人が `#`（**議員死亡後の党指名**。John Lewis死去による空席）。予備選挙票は数字ではなく空欄。候補者数は2人か3人かが確定しない（`non-numeric-primary-votes`）。
   - **2020年IL-04**: 共和党候補者の1人が `#`（**Christopher Lasky死去後の党指名**）。同じく候補者数が確定しない。

## 4. #60（学習と評価）への接続

- 利用可能な行は**913件**（2016年199／2018年241／2020年235／2022年238）。**#60ではこの913件を学習・検証の母数に使い、除外した3件は理由を記録した上で使わない。**除外された3件は、議員死亡後の党指名による空席補充と、全候補者が党帰属書き込み票という特殊な事情によるもので、母集団から外すことによる偏りは3件に限られるが、報告に明記する。
- 学習年→検証年の時間境界は既存バックテストと同じ（2016→2018、2016/2018→2020、2016/2018/2020→2022）。**2022年は既に探索に使用した年であり、確認的な未知の検証ではない。**
- 本Issueは特徴量の**定義**のみを固定する。**閾値・次数・選択規則は#61/#62で事前固定し、2022年で再最適化しない。**

## 5. 限界

1. **リークフリーは構造上の保証であり、実運用の再現ではない。**一般選挙前の時点で候補者数と予備選挙得票がどの精度で知られていたかは、本研究のデータからは検証できない。
2. **FECのExcelは選挙後刊行**である（§1.6）。
3. **母集団は非無作為**である。採用率は年・州で異なり（[#57](https://github.com/SMRI2170/fec-election-analysis/issues/57)）、916件は全下院議席の標本ではない。
4. **小計が一致することは帰属の正しさを証明しない。**§3.4の診断は算術の整合であり、州制度の検証ではない。
5. **星付き表記 `R*` と複合表記の扱いは[#14](https://github.com/SMRI2170/fec-election-analysis/issues/14)の未解決案件に追随している。**帰属すれば一致する地区も、帰属の根拠が固まるまで採用しない。
6. **候補者数の定義はFECの行構成に依存する。**同一候補者が複数行で現れる場合の扱いはFEC IDで1人に統一しているが、FECの表記が変われば値は変わる。
7. **このIssueでは予測精度を測っていない。**特徴量が予測に効くかどうかは[#60](https://github.com/SMRI2170/fec-election-analysis/issues/60)で測る。**本研究は新しい予測アルゴリズムの主張をしない。**
